## Controlling policy language, quoted

### ADR-0079 (`docs/adr/0079-m6.5-one-link-first-contact-exception.md`)

Every telemetry-related clause in ADR-0079 governs **the outbound message and
the URL string**, or **content Proofline places into the linked demo** — not
the hosting platform's own baseline instrumentation:

- *"**no tracking parameters** of any kind (no UTM, no query-string
  identifiers)"* — the bound URL is bare: no query string, no parameter. ✔
- *"**no click-tracking redirect** (the URL must resolve directly to the demo,
  not through a redirect/shortener/analytics service)"* — the URL returns
  HTTP 200 directly, no redirect hop. ✔
- *"**no analytics pixel** anywhere in the message"* — the message contains
  one URL and no image/pixel of any kind. ✔
- *"**no personalized secret or token** in the URL (the same URL must be safe
  to view by anyone who obtains it — it carries no per-recipient identifier)"*
  — the URL is identical for every viewer; PostHog therefore cannot attribute
  a session to Greg Yamin from anything Proofline supplied. ✔
- *"**no real customer or contact data** anywhere in the linked demo"* /
  *"**no form** in the linked demo that collects real contact/customer data"*
  — the demo uses synthetic example inputs only and its form is disabled /
  non-collecting (frozen `demo.builder_brief@3.2`, `builder_story.py` checks).
  PostHog session replay records the *viewer's own* interaction with a
  synthetic page; Proofline places no real customer data into the demo. ✔

ADR-0079's "Still categorically prohibited" list — attachments, a second
link, CRM/calendar/booking links, sequences, automatic follow-ups,
dynamic/personalised tracking links, extra recipients, extra messages —
contains **no requirement that the hosting platform serve zero third-party
analytics or session recording**. ADR-0043's phrase "no links, attachments,
tracking, sequences, or integrations" is about *outreach* mechanisms
(open/click tracking, drip sequences) tied to the recipient — not the
baseline instrumentation any hosted web page carries.

### M6.10 counsel controls

The recorded counsel decisions (`m6.10-hunter-vendor-record-2026-09-06.json`
and the "LEGAL SOURCE ACTIVATION" authorization's 25 sections) govern
**contact sourcing** — directories, contact enrichment, email verification,
LinkedIn read-only use, phone resolution, retention/purge. They are **silent
on demo-hosting telemetry**; they neither permit nor forbid it, because it is
outside their subject matter. Nothing in them is triggered by PostHog or
Cloudflare on the demo page.

## Honest caveat carried forward (a weigh-item for PRIMARY_A, not a breach)

Anyone who opens the demo URL — including Greg Yamin — will have a
**PostHog session-replay recording** created on Emergent's platform
(`session_recording: { recordCrossOriginIframes: true }`), plus a Cloudflare
bot-management challenge/telemetry pass. Proofline did not add, configure, or
consent to this and cannot remove it from a preview-hosted URL; it is not
tied to Greg's identity by anything in the message or URL. This is disclosed
plainly here and in the PRIMARY_A packet — it is a fact for the human
reviewer and the sender to weigh, **not** something this task waives and
**not** an ADR-0079 violation. If PROJECT_OWNER or PRIMARY_A decides host
session-recording is unacceptable for a first contact, the remedy is a
self-hosted static render of the same frozen `demo.builder_brief@3.2` — a
PROJECT_OWNER infrastructure step, outside this task's scope.
