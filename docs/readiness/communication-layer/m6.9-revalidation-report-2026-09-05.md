## 1. The blocker

`docs/readiness/communication-layer/m6.9-stage-b-real-run-report-2026-09-05.md`
§6 recorded that the real A-Plus candidate failed the deterministic validator
on `unsupported_geography`, because the real live A-Plus commercial-HVAC page
title — **"The Austin Commercial AC Repair Company"** — is itself an exact,
licensed, verbatim company-fact phrase that happens to name a place. The
validator's geography check only ever excused a place name coming from a
`SERVICE_AREA_CONTEXT` fact; a place name inside any other category's
verbatim quote had no path to be excused, regardless of provenance.

## 2. Validator rule change — `LICENSED_SOURCE_PHRASE_WITH_GEOGRAPHY`

Files changed: `packages/communication-core/src/opintel_communication/policy.py`,
`packages/communication-core/src/opintel_communication/validator.py`.

- **`policy.place_like_matches(text)`** (new): identical place-token detection
  to the existing `place_like_tokens`, but returns every occurrence as a
  `(token, start, end)` character span instead of a bare set, so a caller can
  reason about *where* a place name appears, not just *whether* it appears.
- **`validator._licensed_source_phrases_with_geography(envelope)`** (new):
  the set of exact, verbatim company-fact phrases — **any** `FactCategory`,
  not only `SERVICE_AREA_CONTEXT` — that themselves already contain a
  geographic token. A phrase qualifies only as the fact's own unmodified
  `verbatim_source_phrase`/`sanitized_phrase`; nothing derived, expanded, or
  inferred belongs here.
- **`validator._licensed_geography_spans(...)`**: the exact character spans
  in the rendered text where one of those licensed phrases occurs verbatim
  (case-insensitive substring match).
- **Geography check (§10)**: for each place token found in the message, its
  occurrences are now excused **only if every single occurrence's span is
  contained inside a licensed-phrase span**. One unlicensed occurrence of a
  place token — an addition, a paraphrase, or a generalization — still fails
  closed exactly as before. Nothing about the SERVICE_AREA_CONTEXT-specific
  Texas/`tx` handling changed; this is a strictly additive exception.

This is generalized: it is keyed on *any* fact whose licensed phrase happens
to carry a place name, bound to the exact phrase text and its provenance —
not an A-Plus- or Austin-specific string check. See §3.

## 5. Deterministic revalidation result

Honest limitation disclosed: Stage B's script persisted the final subject
and body text plus their sha256 hashes, but not the raw provider response
(and therefore not the original `ClaimManifest` the provider itself
returned). A byte-for-byte replay of `OutputValidator.validate()` against
the *exact original candidate object* is therefore not reproducible from
what was saved. The `canonical_claim_reconciler` this validator's contract-v3
path uses treats the provider manifest as **non-authoritative** by design —
coverage, licensing, and strength are independently derived from
prose + envelope, and the manifest is consulted only to raise an
advisory `provider_manifest_disagreement` finding, never to decide
pass/fail — so revalidating with an empty reconstructed manifest against the
exact original text is a faithful substitute for every finding that governs
`passed`, at the cost of one expected extra advisory-only finding
(`provider_manifest_disagreement`, because there is no manifest left to
agree with).

Reconstructed the exact frozen subject + body (unchanged) as a
`GenerationCandidate` with an empty `ClaimManifest` and re-ran
`OutputValidator(contract="v3").validate(envelope, candidate)`:

| | before (2026-09-05, original real run) | after (this fix) |
|---|---|---|
| `passed` | **False** | **True** |
| findings | `unsupported_geography`, `no_company_specific_evidence` | `no_company_specific_evidence` (ADVISORY under v3), `provider_manifest_disagreement` (ADVISORY, a reconstruction artifact — see above) |
| canonical coverage | 1.0 | 1.0 (unchanged) |
| unresolved substantive claims | 0 | 0 (unchanged) |

`no_company_specific_evidence` is, and was already, an `ADVISORY`-severity
finding under contract v3 (`_V2_ADVISORY_CODES`) — it does not fail a
candidate by itself; it is the same "safe-but-generic prose" quality signal
already documented for the Elite shadow candidate, a human-review flag, not
a safety failure. `unsupported_geography` was the only `HARD_FAILURE`
finding, and it is now cleared.

## 6. Result

The existing real A-Plus artifact — unchanged, unregenerated — **now passes
deterministic validation** under the narrow, generalized
`LICENSED_SOURCE_PHRASE_WITH_GEOGRAPHY` fix.
