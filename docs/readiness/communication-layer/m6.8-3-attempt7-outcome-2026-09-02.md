## 5. Why it still fails (on the evaluable sample)

### `structure_violation` — still the dominant blocker; `@7` targets were ineffective

`@7` gave conservative generation targets (subject ≤ 50, body 90–115) inside the
unchanged hard caps, plus an explicit self-count-and-trim step and
prefer-omission instruction. The 29 returned bodies: **mean 135.6 words, range
120–156, 20 of 29 over the 130 hard cap** — essentially identical to Attempt 6
(mean 136.4). `claude-sonnet-5` does not respect the body-length bound under any
prompt framing tried (explicit hard limit in `@6`, conservative target +
self-check in `@7`). **This needs an owner decision** — see §6.

### `claim_manifest_source_mismatch` ×8 — a NEW deterministic false-positive I introduced

All 8 are the same pattern: the model split a single framing sentence into two
manifest entries and typed the lead-in fragment
(`"While reviewing <Business>'s public pages, I noticed"`) as **TRANSITION** with
`licensed_source_ids: []`. The round-3 15b reconciliation calls
`_classify` on that fragment; because it contains "your public pages" /
"<name>'s public pages" it matches `_OBSERVATION_SUBJECTS` and classifies **FACT**
— so the reconciliation treats it as *under-typing* (`declared non-fact-bearing,
wording classifies fact-bearing`) and demands an evidentiary source it does not
have. But the fragment carries **no predicate** — it is a dangling framing
lead-in whose object (and source) sits in the sibling entry. This is a
classification gap: a clause consisting only of a framing act ("… I noticed",
"… we noted") with no object is not a fact-bearing span. Small and fixable (it is
the "obvious framing bug" class of section-F autonomous repair), but a fix
changes `comm.output_validator@3` → a new key → a fresh attempt.

### `cta_semantic_conflict` ×1 — s07 r1

CTA "Would it be worth comparing this simulated step with how requests are
actually handled, to see if it's a useful reference point?" parses to
`OPEN_QUESTION_UNCLASSIFIED`. The "to see if it's a useful reference point"
tail is the classifier gap; the ask itself is a permission-to-compare. Same
class as an Attempt-5 residual; not touched this round.

## 6. Recommendation (owner decision required)

Attempt 7 does not cleanly answer whether the remediated machinery can certify,
because of the HTTP-400 outage. But it *does* establish that the two things a
prompt can fix are fixed (`unlicensed_claim` → 0; drift over-invalidation → 0)
and that **the body-length problem is not promptable** — `@6`'s hard limit and
`@7`'s conservative-target-plus-self-check both land the model at ~136 words.

Options for the owner:

1. **Re-run Attempt 7 unchanged in a stable provider window** (the config/key are
   frozen; the harness is idempotent). This isolates the HTTP-400 contamination
   but leaves `structure_violation` failing ~65–70 % of candidates → still
   NOT_CERTIFIED.
2. **Authorize a proven-safe deterministic body trim** — section B.1 permits it
   *only* with a proof that subject/body + every claim-manifest span stay
   semantically and cryptographically consistent after the trim. This is the only
   path that addresses the dominant blocker without abandoning the provider.
3. **Fix the two deterministic residuals** (§5 framing-fragment classification +
   the s07 CTA tail) under section-F autonomous repair, mint a new key, and
   re-run — but only worthwhile combined with option 2, since structure alone
   still fails the floor.
4. Accept that `claude-sonnet-5` cannot meet the 130-word bound on this task and
   revisit the external contract or the approach.

**No further provider calls, no fix, and no re-run were made** — per the
