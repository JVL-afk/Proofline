### What was adapted from the Haiku track (minimal, section 2)

**Prompt `@8` → `@9`: one line added, nothing removed.** Under `@8`,
`claude-sonnet-5` reads the plural `"candidates"` array as licence to offer
alternatives and returns 2+ candidates. Measured on the real s01 `@8` bundle:
**5,333 output tokens, 36.1 s** (over the frozen 30 s timeout → every call fails
`ProviderUnavailable: TimeoutError`), and a projected 81-call cost of **~USD 5.4**
(over the USD 5.00 ceiling). A trivial connectivity probe and a full 8,000-token
trivial call both returned in ~1 s, and Attempts 5–7 ran this exact config
without systematic timeouts, so the API was healthy — the 2-candidate output was
the cause. `@9` adds: *"the candidates array MUST contain EXACTLY ONE object.
Write your single best email. Do not provide alternatives, variations, options,
or a second candidate."* Measured `@9` single-candidate response: **~1,750
output tokens, ~30 s, ~USD 0.031/call** → 81-call projection **~USD 2.5**, under
the ceiling. No truth / safety / length / disclosure / manifest / closed-set
schema semantics changed.

**Parser hardening (`751566a`).** Exposed by sanity run 1: `claude-sonnet-5`
sometimes emits the `claim_manifest` wrapped as an object (`{"entries":[…]}`) or
once at the top level of the response instead of a bare per-candidate list. The
old parser silently produced a 0-entry manifest for those, and a nested-object
shape raised an uncaught `AttributeError`. `_manifest_rows()` now coerces list /
wrapped-object / top-level shapes and skips non-dict members. Purely additive: a
conformant bare list is unchanged; a genuinely empty manifest stays empty (the
validator's `undeclared_rendered_claim` is the correct signal there); a
per-candidate manifest always wins over the top-level fallback. Not a
certification-key member — the frozen key is unchanged. 5 regression tests; full
suite 1062 passed / 3 skipped; ruff + format + strict mypy clean.

Everything else — validator, projection, compactor, quality assessor,
zero-tolerance semantics, 130-word body cap, 60-char subject cap,
one-CTA rule, original + compacted safety validation — is retained unchanged.

## 7. The residual blocker — a specific decision for PROJECT_OWNER

For the **fourth** Sonnet certification attempt in a row (5, 6, 7, and this
return track), the **provider-authored claim manifest — not the prose — is what
fails certification.** After the parser hardening, exactly one finding family
remains:

**`claim_manifest_source_mismatch` from a redundant source-less wrapper entry.**
On some scenarios `claude-sonnet-5` writes the opening sentence
("While reviewing *Acme*'s public pages, I noticed you list a *Book Now* path
alongside *Chiller Services*") as **one** `DISCLOSURE`/`NON_SUBSTANTIVE` manifest
entry with `licensed_source_ids: []`, **and separately** emits granular `FACT`
entries for *"Book Now path"* and *"Chiller Services"* that cite the correct
`ref` ids. The wrapper entry's span is fact-bearing and cites nothing → hard
`claim_manifest_source_mismatch` (a zero-tolerance code). On other scenarios
Sonnet splits the bare lead-in ("While reviewing *Acme*'s public pages, I
noticed") from the facts cleanly → `_is_framing_leadin` (the D1 fix) exempts the
lead-in → advisory only → PASS.

**Which scenarios hit it is stochastic:** run 1 = s01, s04, s08, s10 (4/9); run 2
= s01, s04 (2/9). Same root cause, different scenarios, stable validator
signatures within the run.

Every fact reaching the reader in the failing candidates **is** licensed (by the
sibling granular entries). No unlicensed claim, no strength inflation, no
manifest dishonesty toward the reader. The wrapper entry is a redundant,
non-load-bearing artifact of inconsistent manifest granularity.

This is **the family pre-identified in the Attempt-6 round-2 residual
attribution** (`docs/…/m6.8-3-attempt6-residual-attribution-2026-09-02.md`,
residual "(1) … 15b `_classify` cross-check").

### Why this was not fixed autonomously

Section 4 authorizes fix-and-rerun for "a small deterministic implementation
defect" but **explicitly forbids changing safety semantics or thresholds even
then**, and directs STOP "if the problem is genuine Sonnet behavior rather than
implementation." `claim_manifest_source_mismatch` is a zero-tolerance safety
code, and the redundant wrapper entry is at least partly genuine Sonnet manifest
sloppiness. Refining it is a PROJECT_OWNER call, not an efficiency call.

### Options

- **(a) Bounded validator refinement + one rerun (smallest step, recommended).**
  Exempt a manifest entry from `claim_manifest_source_mismatch` **only** when
  every fact-bearing token in its rendered span is covered by a *sibling* entry
  in the same manifest that (i) cites a valid `ref` and (ii) declares a strength
  equal to or weaker than the fact it licenses. Any span content not so covered
  keeps the hard failure. This preserves the invariant "no unlicensed claim
  reaches the reader" and removes only the redundant-wrapper false positive. The
  sanity data (0.556 → 0.778 with the parser fix; the *only* remaining family is
  this one) strongly suggests this lands the run at ≥ 0.80 with manifest mismatch
  → 0. Needs explicit sign-off because it touches a zero-tolerance code.

- **(b) Architectural — stop asking the model to author the manifest.** The model
  writes only subject + body; a deterministic pass derives the claim manifest by
  span-matching each body clause to the licensed fact / inference / recommendation
  that supports it (or marking it disclosure / CTA / transition / signature). The
  validator then checks prose ↔ derived-manifest ↔ envelope. This removes the
  single recurring Sonnet failure mode entirely and is model-independent — but it
  is a larger change to the M6.8 contract.

- **(c) Accept that manifest authoring is not a reliable LLM task** and revise the
  certification contract to score the reader-facing prose plus a
  deterministically-derived manifest (a subset of (b)).

**Recommendation: (a).** It is the smallest, most reversible step; it is a
principled, safety-preserving refinement of a family that was already diagnosed
in the Attempt-6 analysis; and the prose quality — the hard part — is already
where it needs to be.
