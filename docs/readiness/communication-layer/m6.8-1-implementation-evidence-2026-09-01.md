## 2. Semantic envelope (`comm.semantic_envelope@1`)

Immutable `@dataclass(frozen=True, slots=True)`, SHA-256 content-addressed (the hash is computed
over a canonical `json.dumps(sort_keys=True)` serialization with the hash field removed, then set).

Carries: business identity (display name + exact public hostname only); **every eligible
`CompanyFact`** as an `EnvelopeFact` with category, sanitized phrase, verbatim source phrase,
evidence IDs, content hash, selector version, `FactStrength`, per-category usage rule,
`rendered_by_deterministic_m5` flag, and a deterministic omission reason for
available-but-not-rendered facts; M3 findings; allowed conditional inferences (with required
qualifiers); allowed recommendations; explicit UNKNOWNs; prohibited claims; economics state;
the structured CTA + `CtaSemanticFrame`; mentionable demo facts (may-say / must-not-say);
required disclosures as placeholders; deterministic reference artifacts (semantic floor +
fallback); the generation request.

`test_response_commitment_is_in_the_aplus_envelope_available_set` proves the A-Plus
RESPONSE_COMMITMENT ("Austin homeowners choose us for flat-rate pricing, fast response times, and
technicians registered with the State of Texas.") is present in the envelope's eligible-fact set
with `rendered_by_deterministic_m5 == False` and a recorded omission reason — available to the
provider, not silently dropped.

`test_envelope_hash_is_stable_and_content_addressed` proves the hash is deterministic across
re-assembly and changes when any carried value changes.

### FactStrength lattice

| Strength | Rank |
|---|---|
| `OBSERVED_PUBLIC_TEXT` | 1 |
| `OBSERVED_AVAILABILITY_SIGNAL` | 1 |
| `PUBLISHED_SELF_CLAIM` | 2 |
| `LICENSED_INFERENCE` | 2 |
| `LICENSED_RECOMMENDATION` | 2 |
| `VERIFIED_FACT` | 3 (ceiling; nothing in Phase 1 reaches it) |

Per-category mapping: INTAKE / COMMERCIAL / SERVICE_AREA → `OBSERVED_PUBLIC_TEXT`;
SERVICE_AVAILABILITY → `OBSERVED_AVAILABILITY_SIGNAL`; RESPONSE_COMMITMENT →
`PUBLISHED_SELF_CLAIM`.

## 3. Claim manifest (`comm.claim_manifest@1`) and independent re-verification

Each candidate returns rendered subject + body **and** a manifest. Each entry: `claim_id`,
`claim_type`, `rendered_artifact`, `rendered_span`, `licensed_source_ids`, `qualifiers`,
`asserted_strength`, `cta_intent`.

The validator re-verifies the manifest independently (`validator.py` check group 15), never
trusting the provider-declared mapping:

| Finding code | Fires when |
|---|---|
| `undeclared_rendered_claim` | a substantive body clause has no manifest entry |
| `claim_manifest_source_mismatch` | a cited source is unknown/empty, or its wording does not cover the span's company-specific content |
| `claim_manifest_strength_mismatch` | `asserted_strength` exceeds the strongest cited source strength |
| `rendered_claim_exceeds_manifest` | the rendered wording sounds stronger than the declared/source strength |

Cross-check tests: `test_undeclared_rendered_claim_fails`,
`test_claim_manifest_source_mismatch_fails`, `test_claim_manifest_strength_mismatch_fails`,
`test_rendered_claim_exceeds_manifest_fails`, `test_correct_manifest_but_unsafe_prose_still_fails`
(a correct manifest does not rescue unsafe prose), `test_unsafe_manifest_but_safe_prose_flagged`
(an unsafe manifest is flagged even when the prose looks safe).

## 4. Output validator (`comm.output_validator@1`)

Pure, offline, fail-closed. 17 numbered check groups: structure bounds; placeholder retention;
no person/contact; number scan (placeholders + quoted phrases stripped first); internal-score
leak; disclosure meaning present; injection markers + reproduced injection-suspected phrases;
**semantic prohibited-concept scan** on all prose clauses; CTA semantic consistency (ADR-0067);
unsupported geography; demo not misrepresented; substantive-clause licensing + conditional
preservation + company-specific clause count; name-only personalization gate; paraphrase fidelity
(quoted fragments must be verbatim licensed-source substrings); claim-manifest cross-checks;
subject independence; UNKNOWN hard-prohibitions.

Licensing vocabulary for substantive clauses is `(fact phrases) ∪ (deterministic engine wording)
∪ (curated safe-framing vocabulary)`. The number/score/contact scans reuse the deployed
`outreach.qc@3` regexes (`_SCORE_LEAK`, `FINANCIAL_EXTERNAL`, `PERSONAL_CONTACT`, `_PLACEHOLDER`)
imported from `opintel_outreach.composition`.

### Semantic prohibited-concept detection

`policy.py::PROHIBITED_CONCEPTS` holds concept patterns (regex families), not literal forbidden
strings, so paraphrases fail. Concepts: MISSED_LEADS, SLOW_RESPONSE, UNDERSTAFFED_OR_BUSY,
NO_CRM_OR_MANUAL, RESPONSE_PERFORMANCE_ASSERTED, AVAILABILITY_TO_RESPONSE (never
licensable-by-presence), QUANTIFIED_BENEFIT, PROBLEM_PRESUMPTION, DEMO_DEPLOYED,
TESTIMONIAL_OR_ENDORSEMENT, URGENCY_OR_SCARCITY, IDENTITY_OVERREACH.

A clause that explicitly preserves an UNKNOWN ("...is not something we can see from the outside")
suppresses the suppressible concepts, so honest UNKNOWN-preserving language passes while
unsupported assertions fail.

## 5. CTA parser (`comm.cta_parser@1`) and ADR-0067

Rule-based, closed vocabularies + regex, no ML. `parse_cta` returns is_question / is_imperative /
presumes_deficiency / ask_objects (closed vocab) / intent_class. `cta_semantic_consistency`
returns the list of sub-reasons a rendered CTA clause violates the `StructuredCTA` /
`CtaSemanticFrame` — the ADR-0066/0067 `RENDERED_CTA_SEMANTIC_CONSISTENCY_GAP` invariant.

- `test_adr_0067_rendered_cta_semantic_consistency_gap_is_caught` — an imperative
  meeting-booking CTA rendered under a permission-question structured frame is rejected
  (`cta_semantic_conflict`). Regression case id `51ee87af09907a072639e7b6`.
- `test_cta_parser_accepts_the_canonical_permission_cta` — "Would it be useful to compare that
  simulation with your actual intake and decide whether the idea is relevant?" is consistent
  (empty reason list).
