## 3. Generation orchestration (`comm.generation_orchestrator@1`)

```
immutable semantic envelope
  → build_prompt_bundle (data-only envelope, injection preamble)     [bundle_sha256]
  → StubProviderAdapter.generate(bundle) → raw JSON + token metadata [raw_sha256]
  → parse_provider_response → N candidates (capped to requested; >requested noted)
  → OutputValidator.validate each                                    [per-candidate ValidationResult]
  → partition pass / fail  (NO regeneration)
  → CandidateRanker.rank(passing)                                    [RankedCandidate + RankScore]
  → GenerationRecord (previous_record_hash → record_hash)            [append-only]
  → RawResponseVault.store(record_hash, raw, retention)
  → human_review_state = PENDING
```

Terminals (all valid, non-send; in `VALID_NON_ERROR_TERMINALS`):

| Terminal | When | Provider called? |
|---|---|---|
| `AI_COMMUNICATION_CANDIDATE_READY` | ≥1 candidate passed validation; ranked; awaiting review | yes |
| `AI_COMMUNICATION_REJECTED` | candidates returned, none passed | yes |
| `COMMUNICATION_NOT_DISTINCTIVE_ENOUGH` | `envelope.has_distinctive_fact()` is False | **no** (short-circuits) |

Default N = 3 (`generation_request.candidate_count`); `requested_candidate_count > 5` raises;
a stub returning more than requested is truncated with a `candidate_cap` diagnostic. No
automatic regeneration loop — a `REJECTED` terminal writes one record and stops.

## 4. `comm.candidate_ranker@1`

Ranks **only** candidates whose `ValidationResult.passed` is True — a FAILED candidate passed
in is a `ValueError`. Never changes the terminal outcome; never exposes any send/eligibility
field.

Eight bounded features, each normalized to [0, 1] (higher = better), fixed weights summing to
1.0:

| Feature | Weight | Direction |
|---|---|---|
| `distinguishing_fact_strength` | 0.25 | strongest licensed fact cited |
| `company_specific_content` | 0.20 | grounded manifest entries / substantive entries |
| `evidence_class_diversity` | 0.15 | distinct evidence categories used / available |
| `brevity` | 0.10 | comfortably under the body-word cap |
| `generic_phrase_ratio` | 0.10 | penalty — generic-token share of body |
| `hedge_density` | 0.08 | penalty — hedges per sentence |
| `quoted_fragment_count` | 0.07 | penalty — quoted fragments over 2 |
| `disclosure_opening_dominance` | 0.05 | penalty — disclosure words share of the opening |

Every `RankScore` preserves all 8 `RankComponent`s (raw value, normalized, weight,
contribution) and the total; `test_ranker_preserves_every_component_and_weights_sum_to_one`
enforces this. Order: higher total, then shorter body, then `candidate_id` — fully
deterministic (`test_ranker_order_is_deterministic`).

## 5. Append-only, hash-chained store

`GenerationRecord` is a frozen dataclass. `compute_record_hash` = SHA-256 over a canonical
serialization of the record body (every field except `record_hash` and the review pointer)
chained with `previous_record_hash`. `append` refuses an out-of-order sequence, a wrong
`previous_record_hash`, or a mismatched `record_hash`. `verify_chain` walks the whole chain.

- `test_store_is_append_only_and_hash_chained` — two runs → sequence 0,1; `r1.previous_record_hash == r0.record_hash`.
- `test_tampering_a_record_breaks_chain_verification` — editing any hashed field fails `verify_chain`.
- `test_out_of_order_append_is_rejected`.

The record holds: envelope SHA-256 + schema version + M2–M5 bundle SHA-256; provider adapter
identity + certification key; `model_placeholder` / `provider_placeholder` /
`config_placeholder` (`<...:pending-m6.8-3>`); prompt-template id + SHA-256 + bundle SHA-256;
raw-response SHA-256 + vault ref + retention metadata; per-candidate `CandidateAuditRow`
(normalized candidate + content SHA-256, claim manifest, `ValidationResult` +
`finding_codes`, `ClaimEvidenceLink[]` mapping every claim to resolved source kinds, rank +
full `RankScore`); passing/ranked id lists; validator/CTA/ranker/orchestrator/store versions;
terminal + status + reason; input/output tokens; `cost_usd = "0.00"`; human-review pointer;
`created_at_epoch_seconds`; diagnostics. `test_record_carries_the_full_audit_surface`.

## 6. Raw-response retention

Only the raw provider response is short-retention. It lives in `RawResponseVault` keyed by
`record_hash`, with an encrypted-ciphertext placeholder, `raw_sha256` kept forever, and a
`RawResponseRetention` (`stored_at`, `max_retention_days = 30`, `expires_at`,
`policy_status = "POLICY_PENDING"`). `crypto_erase` drops the ciphertext and stamps
`erased_at` / `erase_method`; `purge_expired` crypto-erases every entry past its window and
is idempotent.

- `test_expiry_calculation` — `expires_at = stored_at + 30*86400`; not expired at day 29, expired at day 30; `policy_status == "POLICY_PENDING"`.
- `test_crypto_erase_interface_and_idempotency` — second erase is a no-op.
- `test_purge_expired_is_idempotent_and_keeps_hash` — `raw_sha256` survives; `erase_method == "expiry_purge"`.
- `test_normalized_artifact_and_audit_metadata_survive_raw_erasure` — after purge, the record still contains the normalized body, the claim-evidence map, the validator findings for **both** an accepted and a rejected candidate, and `verify_chain` still passes.

30 days is encoded as the proposed technical maximum, `legally_approved = False` on
`RETENTION_PROPOSAL`, `policy_status = "POLICY_PENDING"` on every entry. No background
destructive job runs against production.

## 7. Human-review domain (`comm.human_review@1`)

`HumanReview` is immutable and exact-version-bound (`envelope_sha256` +
`generation_record_hash`, re-checked on every transition). States: `PENDING` →
{`CANDIDATE_SELECTED`, `CANDIDATE_REJECTED`, `ALL_REJECTED`, `ACCEPTED_NOT_DISTINCTIVE`};
the three accept/reject-all states are terminal.

Invariants proven:

- `test_a_validator_failed_candidate_is_structurally_unselectable` — `selectable_candidate_ids` is exactly `record.ranked_candidate_ids`, which is PASS-only; `select_candidate` on a failed id raises `ReviewTransitionError`.
- `test_review_selectable_set_is_exactly_the_pass_validation_ranked_set` — and every id in it maps to a candidate whose `validation.passed` is True.
- `test_review_is_bound_to_exact_record_hash` — a transition against a record with a different hash raises.
- `test_accept_not_distinctive_only_valid_for_that_terminal` — only valid when the record terminal is `COMMUNICATION_NOT_DISTINCTIVE_ENOUGH`.
- `test_reject_all_is_terminal` — a further transition raises.

The review object carries no rendered content and no way to add a claim or clear a finding.
It has no link to contact eligibility or delivery (no such import exists in the package).

## 8. Subject + body atomicity

`normalize_candidate` hashes subject + body + manifest spans as one `content_sha256`
(`test_candidate_content_hash_covers_subject`). The validator already treats both artifacts as
one candidate. `test_safe_body_with_unsafe_subject_fails_the_candidate` is parametrized over
four cases — sensational (`Act now before you lose more commercial work`), unsupported
financial (`A 30 percent lift in booked commercial work`), implied problem (`Fixing your slow
commercial response`), and generic missed-lead (`Every missed call is lost revenue`) — each
with the **proven-good A-Plus body**; every one fails the whole candidate and none reaches
the ranked set.

## 10. Replay / drift

`test_replay_is_bit_identical` — two independent `(store, orchestrator)` runs with the same
envelope, stub corpus, and validator/ranker versions produce identical `record_hash`,
`prompt_bundle_sha256`, `raw_provider_response_sha256`, per-candidate `content_sha256`,
per-candidate `finding_codes`, `ranked_candidate_ids`, and rank totals.

`ProviderDriftDescriptor` records the fields a **live** provider's output will be checked on
at M6.8-3 (`response_fingerprint_sha256`, `normalized_candidate_shas`,
`validator_finding_signature`, `ranking_signature`) and states the rule: replay requires
exact equality; live certification compares fingerprints across repeated real calls and
allows only bounded, documented drift. The stub has a fixed fingerprint by construction.
