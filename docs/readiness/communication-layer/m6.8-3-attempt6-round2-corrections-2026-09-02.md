## 2. Rule 15c — semantic licensing, not literal token overlap (section 2)

15c previously failed a manifest entry when the rendered span carried
> `_MAX_UNLICENSED_WORDS` (2) content words absent from the *literal* text of the
cited sources. Under v2 the check is a bounded semantic-licensing test:

* the cited source's `usage_rule` text is part of `source_words`;
* light deterministic morphology (`_stem` / `_stem_covered`) treats
  `confirm`/`confirms`, `appointment`/`appointments` as covered;
* a word that occurs in the span **only inside a semantic negation**
  (`_only_in_negation`, `_STRONG_NEG` within 42 chars) is not counted as evidence
  of an added affirmative claim;
* source-ID existence (15b), strength ceiling (15d/15e) and the
  "may not add facts or strengthen meaning" rule are all preserved — a fluent
  paraphrase that adds > 2 genuinely-new content words still fails.

Regressions: `test_faithful_paraphrase_within_usage_rule_passes_15c_v2`,
`test_fluent_paraphrase_that_adds_meaning_still_fails_15c_v2`,
`test_stem_covered_light_morphology`, `test_only_in_negation_helper`.

## 3. Rule 4 — numeric strings licensed by an eligible fact (section 3)

`_licensed_numeric_strings(envelope)` extracts numeric tokens that appear verbatim
in an eligible (non-injection) company fact — e.g. `24/7` from a
`24/7 Emergency Service` `SERVICE_AVAILABILITY` fact. Under v2 those strings are
removed from the external text before the number scan. A `FINANCIAL_EXTERNAL` hit
now only raises `unsupported_number` when the matched span actually carries a
digit / currency / `%` — a bare economic phrase such as `lead volume` no longer
triggers the number rule (it remains a `QUANTIFIED_BENEFIT` concern for the
concept scan). `SERVICE_AVAILABILITY` ≠ `RESPONSE_COMMITMENT` is untouched:
`respond … 24/7` still fails via `AVAILABILITY_TO_RESPONSE`. Invented numbers
remain zero-tolerance.

Regressions: `test_licensed_24_7_numeric_string_is_supported_v2`,
`test_licensed_number_does_not_license_response_upgrade_v2`,
`test_non_numeric_financial_phrase_does_not_trigger_unsupported_number_v2`,
`test_invented_number_still_fails_v2`.

## 4. Rule 15b — claim_type reconciliation (section 4)

For every manifest entry, v2 compares `entry.claim_type` with
`_classify(rendered_span, contract="v2")`:

* **declared fact-bearing, wording classifies DISCLOSURE / QUESTION / CTA /
  SALUTATION / SIGNATURE_SLOT** → the span carries no factual assertion; it needs
  no evidentiary licensing. An advisory `provider_manifest_type_mismatch` finding
  is recorded (severity `ADVISORY`, never fails the candidate). A span the
  classifier is merely *unsure* about (NON_SUBSTANTIVE / TRANSITION) is **not**
  waived — it still runs 15b/15c/15d/15e.
* **declared non-fact-bearing (e.g. DISCLOSURE), wording classifies fact-bearing**
  → the entry still runs the full evidentiary checks (a factual span cannot
  escape licensing by being mislabelled), and the mis-type is recorded as an
  advisory finding. `unlicensed_claim` (rule 12) and `undeclared_rendered_claim`
  (15a) already operate on `_classify`, so they catch it independently.

The `@6` prompt now states explicitly that a simulation-preparation / status
sentence is a `DISCLOSURE`, not a `FACT`.

Regressions: `test_provider_overtyped_disclosure_as_fact_is_advisory_v2`,
`test_provider_undertyped_fact_as_disclosure_still_needs_evidence_v2`,
`test_simulation_prep_sentence_classifies_as_disclosure`.

## 5. `no_company_specific_evidence` — advisory (section 5, owner decision)

* Under v2 the finding has severity `ADVISORY`: safe-but-commercially-generic
  prose is a `COMMUNICATION_QUALITY` concern, not a safety failure. It never by
  itself causes a candidate FAIL or `NOT_CERTIFIED`. Human review and M6.8-4 may
  still reject `WEAK` / `NOT_DISTINCTIVE`.
* `_classify` under v2 recognises `"<Business Name>'s public site / pages …"`
  (`_POSSESSIVE_SITE`) as a company-specific public-text observation (FACT), not
  filler.
* Rule 13 under v2 subtracts `_GENERIC_FACT_WORDS`
  (`commercial, hvac, service(s), business, company, work, system(s)`) before
  deciding a clause is company-specific — name-only / category-only overlap does
  not satisfy substantive personalization.
* `COMMUNICATION_NOT_DISTINCTIVE_ENOUGH` remains a valid pre-provider terminal.

Regressions: `test_no_company_specific_evidence_is_advisory_under_v2_only`,
`test_advisory_only_findings_do_not_fail_the_candidate_v2`,
`test_possessive_site_clause_is_company_specific_v2`,
`test_generic_category_overlap_alone_is_not_company_specific_v2`.

`no_company_specific_evidence` finding. Quality never rescues an unsafe
