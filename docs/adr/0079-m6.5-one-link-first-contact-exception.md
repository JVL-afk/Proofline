# ADR-0079: M6.5 one-link first-contact exception (A-Plus pilot #1)

- **Status:** Accepted as a narrow, versioned, one-contact exception. **Not a
  general amendment to M6.5 / ADR-0043.** Exercising it still requires the
  unresolved prerequisites in ADR-0078 §Prerequisites (sender identity, postal
  disclosure, opt-out mechanism, a rendered demo URL, an active signed A-17
  policy) — this ADR defines the *rule*, it does not itself make a send ready.
- **Date:** 2026-09-04/05
- **Decision owners:** PROJECT_OWNER (authorized this exception explicitly,
  "M6.9 PATH B APPROVED FOR ONE BOUNDED A-PLUS FIRST-CONTACT PILOT", §3)
- **Supersedes:** Narrows ADR-0043 for exactly one message; does not repeal it
- **Related:** ADR-0043 (narrow first-production launch envelope), ADR-0078
  (M6.9 first-contact launch review), M6.5 (Live Activation Readiness)

## Context

ADR-0043 fixed the first-production envelope as: US / Texas jurisdiction,
Commercial HVAC inbound lead response/qualification, exactly one recipient, one
plain-text message per authorization, and — categorically — **no links,
attachments, tracking, sequences, or integrations.**

The M4 customer experience (`demo.builder_brief@3.2`, frozen 2026-09-04) depends
on an interactive demo. The M6.9 Path-B decision (2026-09-04/05) explicitly
authorizes exactly one demo URL in exactly one approved first-contact message.
ADR-0043's blanket "no links" rule would make that impossible without an
explicit, scoped exception — silently weakening the general envelope would be
worse than naming the exception.

## Decision

**A-Plus pilot exception, v1** — permits exactly one HTTPS URL in exactly one
approved first-contact message, and only if every condition below holds.

### Permitted (only under all of the following)

- exactly **one** HTTPS demo URL;
- bound to the **exact approved A-Plus demo** — `demo.builder_brief@3.2`, A-Plus
  brief `underlying_brief_sha256 4d9f26412893d85fc21473b65e50466433d3655275957ad3523b20323538636a`;
- present only in the **exact approved first-contact message** — communication
  candidate `body_sha256 184cb2ca18d680d08e7708fdae967e851e2dff53dc0c1394acc7403133e3f419`
  (subject "A quick question about A-Plus AC's intake process") plus resolved
  disclosure slots, unchanged otherwise;
- sent to **one** approved recipient (not yet resolved — see ADR-0078);
- **no tracking parameters** of any kind (no UTM, no query-string identifiers);
- **no click-tracking redirect** (the URL must resolve directly to the demo, not
  through a redirect/shortener/analytics service);
- **no analytics pixel** anywhere in the message;
- **no personalized secret or token** in the URL (the same URL must be safe to
  view by anyone who obtains it — it carries no per-recipient identifier);
- **no real customer or contact data** anywhere in the linked demo;
- **no form** in the linked demo that collects real contact/customer data;
- the demo must **not imply A-Plus ownership or affiliation** — it is a
  simulation the demo itself discloses as unaffiliated;
- the demo carries the **persistent "Simulation · not connected to A-Plus"
  disclosure** on every screen (already enforced by `builder_story.py` check 10).

### Still categorically prohibited (unchanged from ADR-0043)

- attachments;
- any second or additional link (no arbitrary links, no multiple URLs);
- CRM links, calendar links, booking links;
- sequences, automatic follow-ups, dynamic/personalized tracking links;
- any recipient beyond the one approved for this pilot;
- any message beyond the one approved for this pilot.

### Scope and expiry

This exception is bound to **exactly one send**: one company (A-Plus), one
recipient, one message, one URL, one occasion. It does **not** authorize a
second contact, a follow-up, or reuse for any other company or recipient. **Any
mutation of the bound artifacts (demo hash, communication hash, or recipient)
invalidates this exception** and requires a fresh ADR-0079 revision (v2) with
fresh PROJECT_OWNER approval.

This exception does **not** by itself make a send ready — the demo must still be
rendered and hosted by the PROJECT_OWNER (M6.5/M6 have no real infrastructure to
do so), and the sender-identity / postal-disclosure / opt-out prerequisites in
ADR-0078 remain independently required.

## Consequences

- **Positive:** the interactive-demo experience becomes possible for exactly one
  pilot without silently reopening ADR-0043's "no links" rule for future
  automation or scale.
- **Negative:** every future pilot (Elite, additional A-Plus contacts, etc.)
  needs its own bounded ADR-0079 revision — this is intentional friction.
- **Risk:** a tracking parameter or redirect slipping into the URL would breach
  both this exception and ADR-0043's spirit — mitigated by requiring the URL be
  visually inspected as part of ADR-0078's final human-review packet before any
  send.

## Validation

- The final URL string must be inspected against every "Permitted" bullet above
  before use.
- The demo rendering must be checked against `demo.builder_brief@3.2`'s
  `underlying_brief_sha256` before the URL is bound.

## Revisit triggers

- A second contact or second company is proposed → new ADR-0079 revision.
- The bound demo or communication hash changes → this exception is invalid;
  re-approve.
- ADR-0043 itself is revisited for general (not one-contact) link authority.
