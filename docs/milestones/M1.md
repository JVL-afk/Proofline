# Milestone M1 — Research Engine

**Status:** Complete — bounded local M1 scope; production gates remain open
**Authorized:** 2026-08-16
**Completed:** 2026-08-16
**Boundary:** ADR-0005 local research slice; production decisions remain open

## Objective

Given a known business and explicitly permitted public URL, perform bounded HTTP-first research,
capture immutable snapshots, extract only publicly observable material, and expose exact provenance
through the authenticated API and diagnostic UI.

## Included

- Safe URL normalization, DNS/IP and redirect policy, pinned-IP HTTP, and failure classification.
- Bounded retries, timeouts, content/decompression limits, per-domain pacing, caching, and crawl
  budgets.
- Business, research run, page visit, immutable snapshot, structured material, and evidence models.
- Observational extraction of title, metadata, headings, visible text, links, forms, buttons,
  publicly exposed contact strings, structured data, and reliable response/markup technology hints.
- Separate research worker and fail-closed browser-fallback protocol.
- Workspace-authorized API/UI retrieval and adversarial deterministic tests.

## Excluded

Opportunity detection, ROI, scoring, audits, demos, outreach, autonomous agents, mass discovery,
authenticated scraping, CAPTCHA bypass, form submission, third-party login, and live AI/search
providers.

## Completion criteria

- [x] `Business -> Research Run -> Pages -> Snapshots -> Extracted Material -> Evidence` is durable and
  traceable by IDs and hashes.
- [x] Every request remains within explicit host and crawl budgets.
- [x] Untrusted page content cannot control tools or become business-value interpretation.
- [x] Authenticated API and diagnostic UI retrieve runs, pages, snapshots, material, and evidence.
- [x] Deterministic hostile fixtures cover the required M1 safety and failure behaviors.
- [x] A bounded process-level smoke run against the reserved Example Domain completes with exact
  snapshot/evidence provenance.
- [x] All repository, type, lint, test, and security-fixture gates pass.

## Closure verification

- Live HTTP research and browser fallback remain disabled by default and require separate explicit
  settings plus an exact per-run host permit.
- HTTP and browser requests validate public DNS on every navigation; HTTP sockets and Chromium are
  pinned to policy-validated public addresses to prevent DNS rebinding.
- Browser jobs contain no application credentials, inherit only an allowlisted process environment,
  and cannot use persistent profiles, downloads, form methods, cross-host requests, or private IPs.
- Failure records expose bounded categories, attempt numbers, timestamps, and trace identifiers,
  never response bodies or extracted contact data.
- Automated tests use deterministic synthetic transports, resolvers, clocks, hostile fixtures, and
  a temporary SQLite database. The optional reserved Example Domain smoke is not a CI dependency.
- The closure suite uses Node.js 24, npm 11, Python 3.13, and the committed `uv.lock` environment.
- No opportunity detection, valuation, scoring, audit, demo, outreach, search, AI, or autonomous-agent
  behavior is present.

Production launch remains prohibited until the open source, retention/privacy, legal, workflow,
cloud, and browser-containment decisions are accepted.
