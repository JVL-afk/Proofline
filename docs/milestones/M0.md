# Milestone M0 — Decision Closure and Foundations

**Status:** Walking skeleton implemented; decision closure remains open
**Source:** Section 24.0 of `GREENFIELD_ARCHITECTURE.md`
**Scope owner:** To be assigned

## Objective

Create the approved, secure, reproducible foundation on which M1 domain contracts and persistence can be implemented without reorganizing the repository or silently deciding product/compliance questions.

M0 does not deliver product behavior.

### Authorized walking-skeleton extension

On 2026-08-15, the product owner explicitly authorized the smallest M0 vertical path described in architecture section 28: local authentication, a fixture campaign command, durable/retryable execution, one controlled fixture fetch, one evidence item, and API/UI traceability. ADR-0004 constrains this code to local adapters and does not close the production decisions below.

## Workstreams

### M0.1 Decision closure

- Assign accountable owners for A-01 through A-20.
- Resolve the blocking decisions identified in architecture section 25.
- Record each outcome as an ADR or link it to a superseding ADR.
- Confirm initial industry, geography, opportunity types, source policy, provider/data policy, ROI semantics, scoring posture, demo boundary, and human-approval policy.

### M0.2 Repository and engineering foundation

- Maintain the modular monorepo boundaries defined in ADR-0001.
- Approve runtime/package-manager policy and generate reproducible lockfiles.
- Establish formatting, linting, typing, test, dependency, migration, and release standards.
- Add CI gates for every executable package as it is introduced.
- Establish architecture-decision and dependency-update processes.

### M0.3 Environment and platform foundation

- Select cloud, regions, infrastructure tool, Temporal hosting, object-store retention posture, and local-service topology.
- Add reviewed IaC and local environment definitions only after those choices are approved.
- Establish dev/staging/production isolation, workload identities, secret injection, and backup/restore policy.

### M0.4 Identity, authorization, and audit foundation

- Select the OIDC provider and session architecture.
- Implement the minimum workspace/user/membership/role/permission boundary approved by A-03 and A-07.
- Implement server-side authorization primitives and the immutable security/admin audit-event envelope.
- Define whether operators can approve their own work and which actions require step-up authentication.

This workstream may create foundation code and schema only. It must not create business discovery, opportunity, audit, demo, or outreach functionality.

## Explicitly out of scope

- M1 canonical product contracts and business-domain database entities.
- Search, fetch, crawling, browser, AI, opportunity, ROI, scoring, audit, demo, or outreach implementations.
- Provider credentials or live integrations except approved OIDC/platform foundation work.
- Real public-web campaigns or external side effects.
