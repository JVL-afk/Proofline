## Review format

For both Version A and Version B, every case records an integer rating from 1 (poor) through 5
(excellent) for:

- clarity;
- naturalness;
- concision;
- usefulness;
- relevance;
- trustworthiness.

Each case also records paired preference (`A`, `B`, or `TIE`), a material-defect flag (`YES` or
`NO`), and a required note when a material defect is marked `YES`. The assignment hash is stored in
the Instructions sheet, the exact source package hash is stored in every task sheet, and the
reviewer supplies a UTC ISO-8601 completion timestamp.

## Completion and immutable return

Reviewers may save and resume their assigned workbook offline. They must not modify the workbook
filename, frozen metadata, case identifiers, review context, or Version A/B text. An incomplete
workbook remains `IN_PROGRESS`.

After all 105 cases are complete, enter the UTC completion timestamp in Instructions cell `B10`.
From the repository root, replace the reviewer ID in this command with the assigned ID and run:

```powershell
.\.venv\Scripts\python.exe scripts/validate_m66b6_review.py `
  --reviewer PRIMARY_A `
  --workbook outputs/m66b6-primary-review-release-20260820/Tournament-II-Review-PRIMARY_A.xlsx `
  --lock-output local-data/m6.6b-6/locked/PRIMARY_A-review.json
```

The command fails closed unless all assignment, release, package, case, ordering, A/B text, rating,
preference, defect, filename, and timestamp invariants pass. A successful import creates a separate
`LOCKED_PRIMARY_REVIEW` JSON revision preserving reviewer ID, case IDs, both version rating maps,
paired preference, defect and note, assignment/release/package hashes, completion timestamp, and
returned-workbook hash. Existing lock outputs cannot be overwritten.

A correction requires a new output path plus both the prior locked revision and a non-empty reason:

```powershell
.\.venv\Scripts\python.exe scripts/validate_m66b6_review.py `
  --reviewer PRIMARY_A `
  --workbook outputs/m66b6-primary-review-release-20260820/Tournament-II-Review-PRIMARY_A.xlsx `
  --lock-output local-data/m6.6b-6/locked/PRIMARY_A-review-correction-001.json `
  --correction-of local-data/m6.6b-6/locked/PRIMARY_A-review.json `
  --correction-reason "Describe the correction"
```

The correction preserves the prior revision's SHA-256 and supersession reason. It never edits or
deletes the prior locked record.
