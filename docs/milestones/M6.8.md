**Status:** In progress — M6.8-1 (deterministic authority + deterministic gate) implemented and
under owner review; M6.8-2/3 not authorized
**Authorized (design):** 2026-09-01 (owner acceptance of the design proposal with refinements)
**Governing ADR:** [ADR-0077](../adr/0077-evidence-bound-communication-transformer.md) (Proposed)
**Predecessor:** M6.7 deployment chain link 10 (accepted 2026-09-01; deployed image
`sha256:25450867ef8e44ef2339a376e007a8c808fd14cedb39dc2a202f079957b6f039`,
`sampled_slot_m2_m5_runtime_sha256 = a6540437f096ac7b6d0e026fd75ebdffbd5a92a1b77f59e730fb3ee24b3554e7`)

## Objective

Introduce a provider generation step between deterministic semantic authority (M2–M5) and human
review, where the deterministic engine remains authoritative for **what may be said** and the
provider controls only **how** permitted information is expressed. The interface is a structured,
content-addressed semantic envelope — not an email rewrite — and every provider output is
independently re-verified by a deterministic, offline, fail-closed validator before any human sees
it.

The cleanest sequence: deterministic semantic authority → provider generation → deterministic
fail-closed validation → human review → independent contact eligibility → delivery.

## Authority and exclusions

M1–M5 remain read-only and authoritative. The provider is non-authoritative and assumed
compromised. Public website text is untrusted inert evidence and may reach the provider only as
quoted data fields, never as executable instructions. M6.8 contains no live provider call in
M6.8-1 (USD 0), no contact resolution, no delivery, and no send path. No first real contact is
permitted before an explicit **M6.9 — Launch Review** GO.

## Sub-milestones

### M6.8-1 — Deterministic authority and deterministic gate (implemented; under review)

- `ADR-0077 — Evidence-Bound Communication Transformer` (Proposed).
- `comm.semantic_envelope@1` — immutable, SHA-256 content-addressed envelope carrying business
  identity, **every eligible CompanyFact including available-but-not-rendered facts such as
  A-Plus's RESPONSE_COMMITMENT**, M3 findings, allowed conditional inferences and recommendations,
  explicit UNKNOWNs, prohibited claims, economics state, the structured CTA, mentionable demo
  facts, required disclosures, deterministic reference artifacts, and the generation request.
- `comm.claim_manifest@1` — per-candidate structured claim manifest schema; provider-declared
  mappings are not authoritative.
- `comm.output_validator@1` — pure/offline/fail-closed validator with semantic prohibited-concept
  detection (catches paraphrased prohibited claims without the literal forbidden words),
  FactStrength-lattice checks, disclosure/placeholder/no-person checks, economics/number scan
  reusing the deployed `outreach.qc@3` regexes, name-only personalization gate, injection scan,
  subject independence, and independent claim-manifest cross-checks.
- `comm.cta_parser@1` — rule-based CTA classification implementing the ADR-0066/0067
  `RENDERED_CTA_SEMANTIC_CONSISTENCY_GAP` invariant (regression case `51ee87af09907a072639e7b6`).
- Deterministic certification corpus (frozen A-Plus / Elite / E+M envelopes) + adversarial corpus
  (~20 attack categories) using synthetic/stub provider outputs.
- Storage and domain schemas as interfaces only (`ports.py`: `ProviderAdapter`,
  `GenerationStore`); no implementation.
- Pure deterministic tests; no network, no provider, USD 0.

**M6.8-1 success:** the deterministic validator can reliably distinguish permitted communication
from semantically unsupported communication without any live provider call.

### M6.8-2 — Provider adapter and generation runtime (not authorized)

Real provider adapter (ADR-0011 provider-neutral; Anthropic Claude the likely first
implementation under ADR-0048), prompt-template versioning, the injection boundary in the system
/ developer instruction split, cost/token accounting, raw-response retention machinery (proposed
30-day technical maximum, `legally_approved=False`), immutable generation-attempt storage.

### M6.8-3 — Human review and candidate ranking (not authorized)

Deterministic + human ranking of validated candidates without allowing the provider to change
underlying claims, `COMMUNICATION_NOT_DISTINCTIVE_ENOUGH` as a first-class review outcome, and the
human review decision record.
