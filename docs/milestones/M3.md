# Milestone M3 — Evidence-Linked Audit Engine

**Status:** Complete — deterministic local slice; production gates remain open
**Authorized:** 2026-08-17
**Completed:** 2026-08-17

## Objective

Generate a complete opportunity-linked audit from immutable canonical M1/M2 inputs using structured
claims, deterministic rendering, non-overridable QC, and exact version-bound human review.

## Authority and scope

`M1 evidence -> M2 canonical intelligence -> M3 claims -> deterministic rendering -> QC -> review`.
M3 selects and restates truth; it does not create it. Live AI, PDF/export, publishing, share links,
outreach, proposals, demos, and external effects are excluded.

## Eligibility

- Accepted and valid opportunity: full approvable audit.
- Ready-for-review opportunity: internal diagnostic audit; approval prohibited.
- Every other state or no supported opportunity: generation rejected.
- Insufficient economics is displayed only for an otherwise eligible opportunity.

## Structured model

The eleven approved sections contain only atomic `FACT`, `INFERENCE`, `ESTIMATE`, and
`RECOMMENDATION` claims or structured gaps/metadata. Every revision stores an immutable input
manifest, exact lineage, deterministic hashes, QC findings, lifecycle, validity, and review state.

## Exit criteria

- [x] Full and diagnostic eligibility is enforced without manufacturing an opportunity.
- [x] Eleven structured sections and four claim types are implemented.
- [x] Facts, inferences, estimates, and recommendations retain exact typed lineage.
- [x] Unknowns, gaps, assumptions, contradictions, alternatives, and insufficient economics remain visible.
- [x] Deterministic composition and hard semantic QC are provider-free and reproducible.
- [x] Review decisions bind revision/manifest hashes and requested changes create new revisions.
- [x] Freshness consumes versioned states without inventing day thresholds.
- [x] Drafts/reviewer edits are Confidential; no raw page body/provider payload is duplicated.
- [x] API and diagnostic UI expose operations, revisions, claims, QC, provenance, and review.
- [x] Complete M0-M3 validation and final closure review pass.

## Implemented local slice

M3 uses typed core/application/port boundaries, a read-only canonical M1/M2 catalog, append-only
SQLite revisions and reviews, leased three-attempt composition operations, deterministic eleven-
section composition, exact claim lineage, hard semantic QC, freshness-state warnings/gates,
workspace authorization, and a diagnostic API/UI. A future wording-only port has no implementation.
