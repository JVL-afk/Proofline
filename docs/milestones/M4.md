# Milestone M4 — Personalized Demo Engine

**Status:** Complete — deterministic local slice; production gates remain open
**Authorized:** 2026-08-17
**Completed:** 2026-08-18

## Objective

Generate a deterministic, evidence-grounded simulation for the accepted Texas Commercial HVAC
inbound lead-response opportunity and an exact approved M3 audit, using only vetted components,
synthetic data, mock-only actions, and a separate capability-scoped runtime.

## Authority and exclusions

M1-M3 remain canonical and read-only to M4. Live AI, real integrations, public sharing, export,
recording/media generation, outreach, arbitrary generated code, and M5 behavior are prohibited.

## Exit criteria

- [x] Exact accepted-M2 and approved-M3 eligibility fails closed.
- [x] Immutable manifests and revisions preserve complete version lineage.
- [x] One canonical scenario produces interactive, conversational, cue-sheet, and technical views.
- [x] Components, transitions, guards, events, and actions are registered and deterministic.
- [x] All personas and lead inputs are synthetic; actual contact or sensitive data is rejected.
- [x] Every operational receipt is structurally `MOCK_ONLY` and no real adapter exists.
- [x] Runtime-owned disclosure is persistent and cannot be altered by specifications.
- [x] Separate-origin sessions enforce 15-minute issuance and 60-minute runtime limits.
- [x] Revision/session revocation and upstream invalidation fail closed.
- [x] Minimal telemetry excludes text, contact data, tokens, evidence bodies, and transcripts.
- [x] Hard QC, review, lineage, replay, authorization, and hostile fixtures pass.
- [x] Complete M0-M4 deterministic validation passes without live AI or uncontrolled network.
- [x] No M5 functionality or route is introduced.

## Implemented local slice

M4 adds typed domain/application/port boundaries, append-oriented SQLite demo revisions and review
history, a read-only canonical M1-M3 source catalog, leased deterministic composition, immutable
hashed manifests/specifications, a vetted component/question/action registry, a bounded replayable
state machine, synthetic personas, fixed human/safety handoffs, mock-only action receipts, hard QC,
exact review, upstream invalidation, revision/session revocation, 15-minute one-time capabilities,
60-minute runtime sessions, and allowlisted metadata-only telemetry.

The separate `demo-runtime` service has no database or provider/research/application credential. It
renders the runtime-owned disclosure with a strict no-external-connection CSP and exchanges only
the narrow capability/session contracts with the core service. The diagnostic application exposes
manifest, specification, lineage, QC, review, and private launch controls. No public/share/export,
recording/media, live AI, outreach, or real operational adapter exists.
