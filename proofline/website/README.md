# Proofline website

The public company website for **proofline.business**.

Small, static, dependency-free. This is a credibility page for people who look up
the domain — not a product or an app. It does not touch anything else in this
repository.

## Stack

- Plain semantic HTML + one CSS file + ~25 lines of vanilla JavaScript
  (footer year, reveal-on-scroll — the site is fully readable with JS disabled).
- No framework, no bundler, no package to install, no backend, no database,
  no analytics, no third-party scripts, no web fonts (system font stack only).
- Two Python helper scripts (`tools/`) use the standard library only.

The simplest maintainable stack for the job: the files in `src/` **are** the
website.

## Local preview

No install step. From `proofline/website/`:

```
python3 -m http.server 8000 --directory src
```

Then open <http://localhost:8000>. (On Windows: `py -3 -m http.server 8000 --directory src`.)

## Production build

```
python3 tools/build.py            # writes proofline/website/dist/
```

`dist/` is the production artifact — plain files, identical structure to `src/`
with HTML comments and inter-tag whitespace removed. You can equally deploy
`src/` directly; the build step is only tidying.

**Production build output location:** `proofline/website/dist/`

## Test / verify

```
python3 tools/check.py            # checks src/
python3 tools/check.py --dir dist # checks the built output
```

`check.py` fails if it finds any analytics/tracking/advertising token, any
external script or stylesheet, any leaked internal vocabulary or provider name,
a broken internal link, a missing `mailto:andrew@proofline.business`, a missing
privacy page, a changed postal address, or missing SEO/OG metadata.

Manual checklist before deploying:

- [ ] `python3 tools/check.py` passes
- [ ] `python3 tools/build.py` succeeds
- [ ] open the preview on a phone-width viewport — layout holds
- [ ] tab through the page — focus ring visible, skip link works
- [ ] click **Contact Proofline** — opens a mail composer to `andrew@proofline.business`
- [ ] `/privacy.html` loads and the address block is exact
- [ ] no fake customers / metrics / logos / testimonials anywhere

## Deployment

Any static host works. No server-side code, no build server required.

**Recommended (simplest): Cloudflare Pages.**

1. Push this repo to the Git remote Cloudflare Pages can read.
2. In Cloudflare Pages → *Create project* → connect the repo.
3. Build settings:
   - **Framework preset:** None
   - **Build command:** `python3 tools/build.py`
   - **Build output directory:** `proofline/website/dist`
   - **Root directory:** `proofline/website`
   - (or, to skip the build entirely: no build command, output directory
     `proofline/website/src`)
4. Add the custom domain `proofline.business` (and `www.proofline.business`)
   in the Pages project.

Equivalent alternatives, same output directory: **Netlify** (drag-and-drop
`dist/` or connect the repo), **GitHub Pages**, **Vercel** (framework preset
"Other"), or any static file host / S3 + CDN bucket.

### DNS / domain requirements

The domain `proofline.business` is already owned. To point it at the site
(example for Cloudflare Pages — the registrar's DNS panel, **not** done here):

| Type  | Name              | Value                         | Notes |
|-------|-------------------|-------------------------------|-------|
| CNAME | `proofline.business` (apex / `@`) | `<project>.pages.dev`         | apex CNAME flattening, or an ALIAS/ANAME record if the DNS provider supports it |
| CNAME | `www`             | `<project>.pages.dev`         | redirect `www` → apex in the host settings |

- Enable HTTPS / automatic TLS certificate in the host (on by default for
  Pages/Netlify/Vercel).
- Set an email/SPF note: this website does not send email. If Proofline sends
  mail from `andrew@proofline.business`, the SPF/DKIM/DMARC records for the
  sending provider are configured separately from this site.
- After DNS propagates, verify: `https://proofline.business/`,
  `https://proofline.business/privacy.html`, `https://proofline.business/robots.txt`,
  `https://proofline.business/sitemap.xml` all load over HTTPS.

### Social preview image

`assets/og-image.svg` is referenced by the Open Graph / Twitter tags. Some
platforms don't render SVG previews. For the widest compatibility, convert it
to a 1200×630 PNG once and update the two `og:image` / `twitter:image` URLs in
`src/index.html`:

```
# any one of these, whatever is available to you:
npx --yes sharp-cli -i src/assets/og-image.svg -o src/assets/og-image.png resize 1200 630
rsvg-convert -w 1200 -h 630 src/assets/og-image.svg -o src/assets/og-image.png
```

The site works fine without this; it only affects link-preview thumbnails.

## Not included by design

No booking/calendar, no contact form, no newsletter, no accounts, no cookie
banner (nothing sets non-essential cookies), no CMS. Content edits are made
directly in the HTML.
